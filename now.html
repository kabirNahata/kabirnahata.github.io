What I'm doing now

This is a snapshot of where I'm focusing my time and energy right now. Inspired by Derek Sivers' /now page movement—a way to share what I'm up to without the performative nature of social media.

Last updated: January 9, 2025

📚 Currently learning

Deep dive: Data Structures & Algorithms
After finishing CS50x, I realized I could implement basic structures (linked lists, hash tables, trees) but didn't understand when to use each one. I'm working through "Introduction to Algorithms" (CLRS) slowly, implementing everything in C and Python to build intuition.

Right now I'm stuck on: Understanding time complexity analysis beyond Big O notation. I can calculate it mechanically, but I can't yet look at real code and immediately know if it's efficient.

Side studies

  • Web fundamentals — Building this site taught me I don't really understand CSS layouts. Going back to basics with flexbox and grid.
  • Linux/Unix — Reading "The Linux Command Line" and practicing shell scripting. Trying to stop relying on VSCode for everything.
  • Git internals — Not just using git, but understanding how it actually works under the hood. Plumbing commands, the object database, etc.

🛠️ Currently building

This learning journal
You're looking at it! Building a markdown-based blog system from scratch (no Jekyll, no frameworks). The goal isn't just to have a blog—it's to understand how static site generators work by building one.

CS50 Final Project (in progress)
A command-line habit tracker in Python with SQLite. Nothing fancy, but trying to write clean, maintainable code. The challenge is resisting the urge to add features and keeping it simple.

Day 23/100. Focusing on building small tools and scripts instead of tutorial hell. Recent projects:

  • Markdown to HTML converter (baby steps toward my blog generator)
  • Flashcard CLI app for reviewing CS concepts

📖 Currently reading

  • Technical: "Introduction to Algorithms" (CLRS), "The Linux Command Line" (William Shotts)
  • Learning about learning: "Make It Stick" (Brown, Roediger, McDaniel) — changing how I approach studying
  • For perspective: "Range" by David Epstein — helping me feel less anxious about not specializing early

  • Complete 100 Days of Code challenge (for real this time)
  • Publish 8 journal entries (1 technical, 1 reflective per month)
  • Build 3 small projects I'm proud to share
  • Start SAT prep (goal: 1400+ by June)
  • Contribute to 1 open source project (baby contribution is fine)

💭 What's on my mind

The tension between learning and building. I feel torn between "go deep on fundamentals" and "just build stuff." Some days I think I should spend 6 months mastering algorithms. Other days I want to ship projects and learn on the fly. Haven't found the balance yet.

Loneliness in self-directed learning. I miss having classmates. Online communities help, but it's not the same as struggling through problem sets with someone next to you. Trying to find local study groups or online cohorts.

The gap between tutorials and real code. I can follow along with courses, but when I start from a blank file, I freeze. Working on closing that gap by building more without guidance.

🚫 What I'm NOT doing

Saying no is hard, but I'm trying to be intentional about it:

  • Not taking new courses until I finish my current goals (too easy to collect certificates without retaining anything)
  • Not comparing my progress to others on Twitter/LinkedIn (it only makes me anxious)
  • Not trying to learn frameworks before I understand the fundamentals (resisting the urge to jump into React)
  • Not saying yes to every project idea (need to finish what I start)

Reality check: Some weeks I don't code at all. Some days I spend more time organizing my Notion than actually learning. Progress isn't linear, and that's okay. This page is aspirational and honest—I'm working on all of this, but not always successfully.
