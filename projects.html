Learning Journal (This Site)

HTML/CSS Static Site Markdown Node.js

A complete redesign of my personal website into a calm, reflective learning journal. Built from scratch with vanilla HTML and CSS, plus a custom markdown-to-HTML build script for blog posts.

What I learned

  • CSS layouts: Finally understood flexbox and CSS custom properties. Stopped fighting the cascade.
  • Design thinking: Typography-first design, whitespace, color theory. Learned to design for reading, not just looking nice.
  • Static site generation: Built my own markdown parser to understand how tools like Jekyll work under the hood.
  • Writing: Forcing myself to write honestly and reflectively. Harder than writing code.

Biggest struggle: Resisting the urge to add complexity. I kept wanting to use React, add animations, build a CMS. But the constraint of "just HTML/CSS" forced me to focus on content and simplicity. Sometimes less is actually more.

Habit Tracker CLI

Python SQLite CLI

A command-line habit tracking app built for my CS50 final project. Add habits, log progress, view streaks, and generate simple reports—all from the terminal. No web interface, no fancy UI, just functional code.

What I learned

  • Database design: Normalized tables, foreign keys, queries with JOINs. SQL finally clicked.
  • CLI best practices: Argument parsing, error handling, user feedback. Making a CLI that doesn't feel janky.
  • Project structure: Separating concerns, writing testable functions. My first project that didn't feel like spaghetti.
  • Scope management: Saying no to features. Keeping it simple was harder than adding complexity.

What I'd do differently: I hardcoded dates as strings instead of using Python's datetime module properly. Halfway through the project I realized this made calculations messy. Learned the hard way to use the right tools from the start.

Markdown to HTML Converter

Python Regex Parsing

A simple markdown parser that converts .md files to styled HTML. Supports headings, paragraphs, lists, code blocks, and links. Built as a stepping stone toward my blog generator.

What I learned

  • Regular expressions: Finally forced myself to learn regex properly. Still not fluent, but no longer terrified.
  • Parsing fundamentals: Line-by-line processing, state machines, edge cases. Turns out parsing is hard.
  • Testing mindset: Wrote test cases for different markdown patterns. My first project where I tested before submitting.

Reality check: My parser breaks on nested lists and doesn't handle inline code properly. I could fix it, but I realized it's "good enough" for my blog. Perfectionism is the enemy of shipping.

Stanford Code in Place Final Project

Python Karel

A quiz game built as my capstone for Stanford's Code in Place. Used Python dictionaries for questions, random shuffling, and score tracking. My first "real" project that wasn't a tutorial follow-along.

What I learned

  • Decomposition: Breaking a project into functions. This was the first time I really understood "top-down design."
  • User input validation: Handling unexpected input without crashing. Users will always do things you don't expect.
  • Comments and documentation: Writing code someone else could read (my section leader had to review it).

Honest reflection: Looking back, the code is pretty rough. Lots of global variables, repetitive logic, no error handling. But it worked, and I was proud of it. That counts for something.
